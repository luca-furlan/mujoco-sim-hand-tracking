COSA FARE (soluzione concreta — tutto sul PC Windows, VR col Quest)
===================================================================

Perché Docker: serve solo se vuoi Linux/CI. Per te il percorso reale è QUESTA cartella g1-local.

PASSO 1 — Una tantum---------------------
Apri PowerShell nella cartella g1-local:

  Set-ExecutionPolicy -Scope Process Bypass
  .\SETUP.ps1

Scarica Menagerie (solo unitree_g1), crea .venv, installa MuJoCo.

PASSO 2 — Avvio simulatore (tutto assieme: HTTPS + sim + WebSocket)
--------------------------------------------------------------------
  .\START.ps1
  (oppure dalla cartella H-ACK: ..\AVVIA_G1.ps1)

  Equivalente manuale: .\.venv\Scripts\python.exe server.py

Il server usa UNA porta: HTTPS 8443 (WebXR e wss:// richiedono HTTPS).

Sul PC apri nel browser:
  https://127.0.0.1:8443/
Accetta l’avviso certificato (Avanzate → continua). Prova WASD + Q/E.

PASSO 3 — Quest (WebXR)
------------------------
1) Stessa Wi-Fi del PC.
2) IP PC es. 192.168.123.6
3) Sul Meta Quest Browser apri:
     https://192.168.123.6:8443/
4) Accetta il certificato.
5) Firewall Windows: consenti TCP 8443 in entrata (rete privata).
6) Tocca "VR".

NOTA: http://…:8000 non è più l’URL normale. Solo se imposti HTTP_ONLY=1 (debug senza VR su IP LAN).

Se WebXR ancora non parte: il browser Quest è schizzinoso con certificati locali.
Allora usa un tunnel HTTPS “vero” (account gratuito):
  - installa ngrok, da PC: ngrok http 8000
  - apri l’URL https://....ngrok-free.app sul Quest (stesso WS/wss verso quell’host).

LIMITI onesti
-------------
- Io nel repo posso darti sim + pagina + istruzioni. Non posso compilare un APK Unity sul tuo PC senza Unity installato.
- Se WebXR sul Quest continua a fallire, l’unica alternativa robusta è un’app Unity (Meta XR) che mandi comandi al PC (vedi g1-sim-docker/VR_QUEST.txt e udp_zmq_bridge.py).

In sintesi: inizia da PASSO 1–3 qui sopra; è il massimo che si può chiudere solo con Python + browser Quest.
